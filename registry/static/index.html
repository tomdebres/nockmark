ZK mining — Tip5 hashes per second, CPU and GPU
#hardwaretier verified hashes/sgrind-window ±σprover nock/dayusd/day
Loading verified runs…

Since block 147,500 (Anthropos, ZK proof version 5) a ZK mining attempt is one Tip5 hash of proof object 0 — the puzzle for one nonce — and a miner builds the full STARK only for a nonce whose hash meets the target. So this board ranks hashes per second. A run grinds nonces for a commitment derived from this server's challenge, against a target it issued, and proves k winners. For each one the server re-derives the hash from the proof itself, checks the commitment, the length, the version and the target, and verifies the STARK twice, with upstream's native verifier and with the consensus Hoon verifier. Only then does it credit k × the expected hashes per win, over the window it observed. A nonce counts once, whatever the proof bytes.

Tier is the expected hashes per win a run asked for. Clients size it at twice their own proving time, so the proving inside the window costs every host the same third of its true rate, and the ranking holds. CPU and GPU rows rank together: the GPU path is upstream's open-source CUDA V5 search, which only finds winners; each one is re-checked and proved on the CPU, then verified here like any other.

AI-PoW — MAC-equivalents per second, CPU and GPU
#hardwarestatementtier verified MAC-equiv/sgrind-window zk-attempt-equiv/s±σprover nock/dayusd/day

The Logos AI-PoW puzzle (INT8 tiled matmul + recursive STARK certificate), verified the same way: every rate computed by this server from certificates it checked, of challenges it derived. Two statements share this board — dense, the single-tile benchmark, and canonical MoE, the block mainnet AI miners actually run — because MAC-equivalents is the unit consensus itself uses to compare work of different shapes. Tier is the expected grind attempts per win the run was measured at — clients pick it, so fast hardware can grind long enough to be measured rather than being drowned out by the fixed certificate-proving cost inside the window. Picking a tier cannot inflate a number: an easy tier earns less credit against that same fixed cost, and a hard one has to actually be ground out, attempt by verified attempt. CPU and GPU rows rank together: the device only searches for jackpots, and every win it finds is re-checked and certified on the CPU before this server verifies it.

New wins are verified under mainnet's current rules (Hardened since block 154,500, exact MoE routing since 170,000); a legacy certificate is rejected. Only those rows are ranked. Rows accepted before that are marked legacy rules and listed after them, unranked.

These GPU figures are behind upstream. They were measured at pin c8d6b13e with the generic CUDA kernel, which still serves this shape. Two days after that pin, upstream made a peak kernel on its own dense shape the production GPU path and reports the same card going from 0.19 to 335 TMAC/s — about 1,700× — so treat the GPU rows here as a floor for the hardware, not a measurement of it. That shape and a GPU re-run are next on the list. (Nockchain also admits mining inside real model inference, at throughput comparable to the optimised dedicated kernel; the interesting part there is that the compute is dual-use, not that it is faster.)

Each mark in the second column is drawn from that run's challenge nonce — a fingerprint of the workload the machine actually proved. Hardware descriptors are self-reported; rates are not.

nock/day and usd/day are estimates: the attempt-lottery model at the difficulty and price observed above, shown only when this instance has actually observed them. They exclude electricity, hardware, pool fees and solo-mining variance, and both difficulty and price drift — so read every figure as a snapshot, not a forecast. /economics publishes every input, so you can redo the arithmetic yourself.
